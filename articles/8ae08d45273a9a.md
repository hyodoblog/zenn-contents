ついに Stripe Terminal が日本でも手に入るようになり、3 年間温めていた構想を実現できました。先日ようやくハードウェアが届き、リアルカードを使った決済のテストも完了したので、セットアップから動作確認までの流れをまとめます。

## 3 年越しで触れた Stripe Terminal

- 2021 年頃から国内ローンチの噂はあったものの、長らく一般提供がなく、導入計画だけが先行。
- EC とオフラインをシームレスに繋げたいという要件があり、Terminal の提供開始をひたすら待ち続けていました。
- 2024 年春にやっと日本のアカウントでも申し込み可能となり、即座にベータ申請してデバイスを発注。

## ハードウェアと環境の準備

1. Stripe ダッシュボードで Terminal のベータ有効化 + ロケーション設定。
2. BBPOS WisePOS E を選択し、到着後に最新版ファームウェアへ更新。
3. 開発用環境として、フロントエンドは Next.js + Stripe.js、バックエンドは Cloud Functions で REST エンドポイントを用意。
4. `terminal` SDK を利用するために、サーバー側で Connection Token 発行のエンドポイントを実装。

```ts
// Cloud Functions (TypeScript) でのエンドポイント例
override export const createConnectionToken = onRequest(async (_req, res) => {
  const token = await stripe.terminal.connectionTokens.create();
  res.json(token);
});
```

## ペアリングとテストフロー

- 端末を起動して Wi-Fi を設定し、Pairing Code を発行。
- フロントエンドから`Terminal.connectReader()`を呼び出し、Connection Token 経由で端末と紐付け。
- `collectPaymentMethod → processPayment → capturePayment`という標準フローを実装。
- テストモードのままでも、読取自体は手元のリアルカードで問題なく可能でした（決済は承認されず、Stripe 側で自動的にテスト結果として扱われる）。

## リアルカード決済テストでわかったこと

- タップ・挿入のどちらも挙動がスムーズ。NFC の反応速度は従来の国内決済端末に比べても遜色なし。
- ダッシュボードのタイムラインで、どの端末が決済を処理したのかが即座に確認できる。
- テストモードでリアルカードを使う場合は、Stripe のドキュメントにもあるとおり請求書作成や請求確定は走らないが、フロントのユーザー体験はほぼ本番と同じ。
- 端末から発行されるレシート印刷は標準ではないため、必要な場合はサーマルプリンタ連携を別途検討する必要あり。

## これからの展望

- 直近はイベント出店や「焼肉処 味来」での導入テストを予定し、端末の動線やスタッフオペレーションの最適化を図る計画。

3 年越しに念願の Stripe Terminal に触れられた喜びが大きく、リアルカードを使ったテストでようやくスタート地点に立てました。これから本番環境での運用に向けて、ユーザー体験とバックエンドの信頼性を高めていきます。
