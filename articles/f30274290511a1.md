# はじめに

LINE ミニアプリの運用中、Google Cloud の請求額が 1000 万円を超えたことがありました。

エラーを早く見つけるために作った通知の仕組みで、大量のログが発生していたことが原因でした。発覚したときの対応と、その後に見直したことをまとめます。

# 事象

発生時期は 2023 年 8 月 22 日から 9 月 2 日。この期間に請求額が急増しました。

こちらが実際の請求ダッシュボードです。途中から費用が急増しているのが分かります。

ちなみにこのまま気づかず放置していた場合、着地見込みは **月あたり約 4600 万円**という表示になっていました。

# ストーリー

## 発覚したときのこと

とある LINE ミニアプリ案件で、Cloud Run や Cloud Functions のエラーログを Discord に通知する仕組みを作っていました。バグ報告をなるべく早く察知するためです。

3 ヶ月ほど正常に動いていたのですが、2 週間ほど一切通知が来ない時期がありました。「ようやくバグのないサービスができたか」と少し考えはしましたが、そんなことはないだろうと手動でログを確認しました。

そこで月額請求が 1000 万円を超えていることに気づき、「？？？？」となりました。数分間思考が止まり、お支払いログを見たらすでに支払い済みでした。

さらに無量空処をくらい、10 分ほどパソコンを閉じて散歩しました。その後戻って、原因を調べ始めました。

## 大量のログが発生していた

費用が発生していたのはログのストレージでした。1 ミリ秒単位で同じエラーが数百〜数千行ほど出ており、1 秒間で約数万行のログになっていました。

エラーを検知するための仕組みが、エラーを起こしていました…。

まず費用の増加を止めるため、通知に使っていた Cloud Functions と Pub/Sub を削除しました。

## クライアントへの連絡

原因を特定する前に、クライアントへ連絡していました。日曜日のランチの時間帯で、返信が来たのは 1 時間ほど後でした。

その頃には該当リソースの削除まで終わっていたため、急遽 Zoom をつなぎ、発生したことと対応内容を説明しました。

## Google Cloud への問い合わせ

費用の発生箇所は分かりましたが、なぜログが大量に出たのかはまだ分かっていませんでした。

ログを見る限り、Pub/Sub 側でエラーが起きており、その先で動くはずの Functions は実行されていません。Functions が動いてエラーになっているなら、こちらのコードを直せば済む話。ところが今回は Pub/Sub 側のエラーが延々とログに吐かれ続けており、自分の実装だけでは説明のつかない挙動でした。

Google Cloud へ、請求データとログのスクリーンショットを添えて問い合わせました。通知の仕組みで起きたエラーと、短時間に大量のログが出た経緯を説明しています。

## 返金について

サポートとのやり取りの結果、クレジットの形で全額が戻ってきました。

今回は返金されましたが、同じことが起きても返金されるとは限りません。運用側で気づけるようにする必要があるため、次の対策を行いました。

# 対策

請求通知とエラー通知の 2 点を見直しました。

## 1. 予算アラート・請求通知の設定

今回、請求額が 1000 万円を超えるまで増加に気づけていませんでした。

そこで Cloud Billing の **予算（Budget）とアラート** を設定。月額の想定コストに対して 50% / 90% / 100% の閾値を超えたら、即メール・Discord に通知が飛ぶようにしました。

毎月の目視確認に加えて、想定額を超えた時点で通知が届くようにしています。

## 2. エラー通知の見直し

通知の仕組み自身が壊れた場合も考えて、次の方針で見直しました。

- 同じエラーは一定時間分をまとめて通知し、通知回数を制限する
- 通知処理のエラーを、同じ通知経路へ戻さない
- 通知が止まったことを確認できるよう、定期的な生存確認を送る

# まとめ

バグの通知が来なくなったので調べたら、通知の仕組みで高額な費用が発生していました。自分で作った通知が止まったときに、もっと早く確認すべきでした。

同じような仕組みを運用している方は、通知処理が失敗した場合の動作も確認してみてください。
