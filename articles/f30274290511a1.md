# ストーリー

## 発端

とある LINE ミニアプリ案件を対応しているなか、バグ報告をなるべく早く察知したいと考え、Cloud Run や Functions でエラーログが流れたらすぐ Discord に通知する仕組みを作りました。
3 ヶ月正常に運用できていたのですが、2 週間ほど一切通知が来ないタイミングがあり「ようやくバグのないサービスができたか」と少し考えはしましたが「そんなことはないだろう」とサービスログを手動で見に行ったところ、月額請求額が 1000 万円を超えており、「？？？？」となり無量空処状態になりました。数分間思考停止後お支払いログを見てみるとすでにお支払済みでした。さらに無量空処をくらい、10 分ほどパソコンを閉じ散歩しました。その後現場に復帰し、冷静に原因を探しを始めました。

## 原因

調査した結果、原因は大量のログ吐き出しによるストレージの容量でした。1 ミリ秒単位で同じエラー分が数百〜数千行ほど図れており、1 秒間で約数万行のログが出力されてました。ログの内容は全部同じで、無限に大量発生してました。
つまり*エラーを検知する仕組みがエラーを起こしてました*...
一旦エラー検知機能に使用していた Functions と PubSub ごと削除することでそれ以上の費用発生を防ぐことができました。
放置していたら月 4600 万円の費用が発生する見込みでした。

## クライアントへ連絡

原因を特定する前にクライアントに連絡をしてました。ちょうど日曜日のランチタイミングだったので返信は 1 時間後でした。返信が来た頃には原因追及と対策は完了していたので、急遽 Zoom をしました。
