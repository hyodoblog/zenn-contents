クライアントへの更新報告を Vercel で共有していた人に、Claude のアーティファクトを紹介する機会がありました。

「アーティファクトにまとめて」と頼めば作れますが、初めて使う場合は、何ができてどう共有するのかも知りたいと思います。今回は更新報告を例に、作成・共有・更新の手順をまとめます。

:::message
クライアント名・業務固有の用語は伏せ、例は架空の内容にしています。通常の Claude チャットのアーティファクトが対象です。Claude Code・Cowork の機能は含めません。仕様は 2026 年 9 月 11 日時点の公式資料に基づきます。
:::

## アーティファクトとは

**Claude が作った文章や図、Web ページなどを、チャットとは別の画面で表示・編集できる機能です。**

たとえば「今回の変更点を報告ページにして」と頼むと、会話の横にページが表示されます。「見出しを変えて」と追加で頼めば、その成果物を修正できます。[Claude 公式の概要](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

普通の回答を読むだけでなく、人に見せる形に整えて、何度か直して使うときに便利です。

## 作れるもの

公式には文書や HTML のページ、図、操作できる画面などが例として挙がっています。クライアントワークなら、次のように使えます。

| 作るもの | 使い道 |
| --- | --- |
| 更新報告ページ | 変更前・変更後と、確認してほしい点を並べる |
| 操作マニュアル | 手順や注意点をまとめる |
| フロー図 | 予約や申し込みの流れを説明する |
| 画面の見本 | タブやボタンの動きを見せて、認識を合わせる |

画面の見本を作っても、実際の予約や決済まで動くとは限りません。説明用なら、そのことをページにも書きます。

### まずは、この依頼文で試す

Claude のチャットに、次のように入力します。HTML は、ブラウザーにページを表示するための形式です。

```text
以下の架空の更新内容を、クライアント向けの
HTML のアーティファクトにまとめてください。

・予約フォームに日付の入力例を追加しました
・入力例の表現が分かりやすいか確認してほしいです
・予約完了メールの文面変更は未対応です

「変更点」「確認してほしいこと」「未対応」に分け、
スマホでも読みやすくしてください。
版番号は v1 とし、説明用の架空の例だと明記してください。
事実にない効果や数値、外部通信の機能は追加しないでください。
```

できたページの内容も確認します。「入力ミスが減りました」など、測っていない成果が足されていたら直します。実際の案件では、AI への入力が許可された情報だけを使います。

## 共有と更新の方法

### 共有する

共有する前に、使っているプランで誰が閲覧できるかを確認します。公開リンクは、送った相手以外でも開けます。

| プラン | 操作 | 見られる人 |
| --- | --- | --- |
| Free / Pro / Max | Publish（公開） | リンクを知っている人なら誰でも |
| Team / Enterprise | Share（共有） | 同じ組織のメンバー。ログインが必要 |

公開してよい内容なら、アーティファクトの対象の版を開き、「Publish」からリンクを取得して渡します。基本的な閲覧には、相手の Claude アカウントは不要です。

組織内なら「Share」→「Share & copy link」で共有します。プロジェクトから作った場合は、相手にもそのプロジェクトへのアクセスが必要です。[共有の公式手順](https://support.claude.com/en/articles/9547008-publish-and-share-artifacts)

組織外のクライアントに機密資料を渡したい場合は、コピーやダウンロードで取り出します。そのうえで、相手と合意した、閲覧者を制限できる共有先へ置きます。

なお、組織内共有では生成元の会話の添付ファイルにも相手がアクセスできます。ページに載せた内容だけでなく、添付も確認してください。

### 更新する

元の会話で、対象のアーティファクトを指定して修正を頼みます。

```text
今の報告ページを修正してください。
「未対応」に「次回の対応範囲は別途相談」と追記し、
版番号を v2 にしてください。それ以外は変えないでください。
```

修正後は、次の順に確認します。

1. アーティファクト内で、修正内容と版番号を確認する
2. 修正版の公開・共有画面を開き、必要な操作をしてリンクを取得する
3. 渡すリンクを別のブラウザー環境で開き、修正版が見えることを確かめる
4. URL が変わった場合は、相手に新しいリンクを渡す

編集と版の切り替えは公式に案内されています。ただし、**編集内容が既存の公開 URL に自動反映されるかは、今回確認できていません。** 手元の編集画面だけで完了とせず、相手に渡すリンクで確認します。[編集方法](https://support.claude.com/en/articles/9487310-what-are-artifacts-and-how-do-i-use-them)

ファイルで渡した場合は、修正版を取り出し、共有先のファイルも更新します。

## Vercel と使い分けるなら

**アーティファクトは Claude で成果物を作る機能、Vercel は Web サイトやアプリを配置して配信するサービスです。** この配置作業を「デプロイ」と呼びます。[Vercel の公式説明](https://vercel.com/docs/deployments)

今回の用途なら、次のように考えると選びやすいです。

| やりたいこと | 選び方 |
| --- | --- |
| 更新内容を見やすく説明したい | アーティファクトで報告ページを作る |
| 実際のサイトやアプリを触って確認してほしい | Vercel などに動作確認用の環境を用意する |
| クライアントだけに見せたい | どちらでも、閲覧者を制限できる共有方法を選ぶ |

アーティファクトでも操作できる画面は作れますし、Vercel に報告ページを置くこともできます。用途は重なりますが、報告資料を作るために毎回 Vercel へデプロイする必要はありません。

ただ、私が最初に勧めたときの「アーティファクトのほうが安全」という説明は不十分でした。公開リンクを使えば、アーティファクトも第三者が読めます。

一方、Vercel にもアクセスを制限する機能があります。2026 年 9 月 9 日には、全プランで本番を含む Vercel Authentication の保護が追加料金なしになりました。有効化と保護範囲の設定は必要です。[Vercel の変更案内](https://vercel.com/changelog/protect-production-deployments-for-free-on-every-plan)

更新報告を作るには便利ですが、共有するときは載せた内容と閲覧できる人を確認して使いたいです。詳しく点検する場合は、[セキュリティチェックリスト](https://github.com/hyodoblog/zenn-contents/blob/main/docs/security-checklist/checklist.md)の AI 入力や情報の共有に関する項目も参考にしてください。
