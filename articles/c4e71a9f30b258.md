Stripe Terminal の Apps on Devices で、決済端末 12 台にアプリを配信しています。運用開始前に鍵の保管状況を確認したところ、2 か月前に作った署名鍵のパスワードを控え忘れていました。

GitHub Secrets には登録していたので CI のビルドは通りますが、手元では取り出せない状態です。今回は、新しい鍵で更新できるか Stripe のサポートへ確認した内容と、入れ替えの準備についてまとめます。

:::message
本記事は業務システムの開発に伴走した記録です。クライアント名・店舗名・アカウント ID は伏せ、パッケージ名は `jp.example.tipping` のようなプレースホルダに置き換えています。
:::

同じ案件で、Stripe Terminal の接続エラーに 3 日ハマった話も書いています。あわせてどうぞ。

## つくっていたもの

インバウンド向け飲食店グループの、チップ決済アプリです。

- **端末**: Stripe Reader S700 を 12 店舗に 1 台ずつ
- **アプリ**: React Native（Android）を Apps on Devices で配信
- **バックエンド**: Next.js on Vercel
- **配信**: 12 店舗を 1 つの Deploy Group にまとめ、承認後は自動配信

署名鍵は 2026 年 7 月に作りました。`keytool` を叩いて、その場でパスワードを決めて、GitHub Secrets に登録する。よくある手順です。

```bash
keytool -genkeypair -v \
  -keystore release.keystore -alias example-tipping \
  -keyalg RSA -keysize 2048 -validity 10000
```

## キーストアはあるが、パスワードがない

作成から 2 か月後、運用開始の直前に保管状況を点検しました。キーストアのファイルはあり、CI のビルドも通っています。ただ、パスワードを保管した場所が見つかりませんでした。

## 作業ログと保管先を確認した

まず作業ログを全文検索しました。当時のやり取りはすべて残っているので、値が貼られていれば見つかるはずです。

```bash
# パスワード名と値が並んだ形を探す
grep -oE '(KEYSTORE_PASSWORD|KEY_PASSWORD|storePassword)\s*[=:]\s*\S+' work.log
```

0 件でした。

`keytool` のプロンプトで入力したパスワードは、画面にもシェル履歴にも残っていませんでした。

1Password にもありませんでした。当時の手順書には「キーストアの原本は 1Password 等で保管」と自分で書いてあります。書いた本人が、原本だけ保管してパスワードを保管していませんでした。

GitHub Secrets には登録済みです。ただし GitHub は登録後の値を表示しません。

```bash
gh secret list -R owner/repo
# ANDROID_KEYSTORE_BASE64    2026-07-11T17:00:10Z
# ANDROID_KEYSTORE_PASSWORD  2026-07-11T17:00:54Z
# ANDROID_KEY_ALIAS          2026-07-11T17:00:20Z
# ANDROID_KEY_PASSWORD       2026-07-11T17:01:21Z
```

登録した名前と日時は確認できますが、値を表示することはできません。CI で使う分しか保管できていませんでした。

## 署名鍵を変えた場合の更新が心配だった

Android アプリの更新では署名鍵の互換性が問題になるので、Apps on Devices でも鍵を変えると更新できなくなるのでは、と考えていました。

この時点で考えた対応は、次の 2 つです。

| # | 案 | 代償 |
| --- | --- | --- |
| 1 | 12 台を回収して入れ直す | 全店舗の営業に影響。現地作業 |
| 2 | パッケージ名を変えて別アプリとして出し直す | 審査のやり直し。旧アプリの削除 |

ただ、CI は動いていたので、すぐに配信できなくなったわけではありません。まずは端末の回収や別アプリとしての登録が本当に必要なのか、確認することにしました。

## Stripe のサポートに確認した

自前で判断する前に、Stripe のサポートに聞きました。社内チームで確認したうえで、次の回答が返ってきました。

> 新しい署名鍵を使用して、既存のアプリに新しいバージョンの APK をアップロードできることを確認いたしました。現在の App ID およびパッケージ名はそのままご利用いただけます。
>
> 新しいアプリのバージョンをアップロードし、承認された後、12 台のリーダーが含まれる既存の Deploy Group に対して、新しいデプロイメントを作成してください。その後、通常のデプロイ手順により、各リーダーへ新しいバージョンがリモートで配信されます。
>
> アップデートの配信前に、既存のアプリをアンインストールしたり、リーダーを工場出荷時の状態にリセットしたり、設置場所から回収したりする必要はありません。

この回答で、既存の App ID とパッケージ名を使い、新しい鍵で署名した APK を配信できると分かりました。

## 入れ替え前に確認したこと

### 公式ドキュメントに書いてあること

デプロイのページには、バージョンについての制約が明記されています。

> 以前のバージョンのアプリをデプロイすることはできません。アプリのバージョンは、現在デプロイされているアプリよりも新しいバージョンである必要があります。

インストールの経路についても記述があります。

> デプロイ中、アプリはすぐにデバイスに送信・ダウンロードされ、デバイスの再起動後にインストールされます。デバイスは 24 時間ごとに再起動し、更新プログラムが自動的に適用されます。

### 書いていないこと

署名鍵についての記述は、私が探した範囲では見つかりませんでした。overview・deploy・submit・troubleshooting のいずれにもありません。少なくとも、確認したページだけでは鍵を変更できるか判断できませんでした。

仕組みも公開されていません。ここは推測せず、**サポートから得た回答を事実として扱います**。通常の `adb install` や Play ストアの更新とは経路が違う、とだけ言えます。

### 端末にデータが残っていないかを確かめる

更新時にローカルデータがどう扱われるかは、この回答だけでは分かりません。そこで、消えると困るデータをアプリ側で保存していないか調べました。

```bash
grep -rn "AsyncStorage\|MMKV\|SharedPreferences\|EncryptedStorage" app/src
```

0 件でした。設定はビルドに埋め込み、接続トークンは毎回バックエンドから取る作りだったので、端末に永続化しているものがありません。ただし、この検索だけで SDK などが保存するデータまで確認できたわけではありません。

### 入れ替えの手順

新しい鍵を作り、Secrets とバージョンを更新して配信する手順を整理しました。

```bash
# 1. 新しいキーストアを作る。パスワードは対話入力なので、決めたら即 1Password へ
keytool -genkeypair -v \
  -keystore release-new.keystore -alias example-tipping \
  -keyalg RSA -keysize 2048 -validity 10000

# 2. Secrets を差し替える。値は対話で貼るのでシェル履歴に残らない
base64 -i release-new.keystore | gh secret set ANDROID_KEYSTORE_BASE64 -R owner/repo
gh secret set ANDROID_KEYSTORE_PASSWORD -R owner/repo
gh secret set ANDROID_KEY_PASSWORD     -R owner/repo
```

PKCS12 形式なので、キーストアのパスワードと鍵のパスワードは同じ値になります。エイリアスを変えなければ `ANDROID_KEY_ALIAS` はそのままで構いません。

あとは `versionCode` を上げてタグを打ち、生成された APK をアップロードして、既存の Deploy Group に新しいデプロイメントを作ります。

### いつやるか

私たちは**実際の決済がまだ 0 件の時期**に入れ替えることにしました。理由は 2 つあります。

1. 失敗してもお客様に影響が出ない
2. 機能変更と混ぜないので、問題が起きたときに原因を切り分けられる

新しい鍵で 12 台への配信が完了するまでは、旧キーストアなど、保管できている既存の署名情報も保持する予定です。Secrets を同じ名前で上書きすると旧値を取り出せなくなるので、切り替える前に CI 側の保管方法も整理する必要があります。

## おわりに

署名鍵のパスワードを控え忘れていましたが、今回の Apps on Devices では、新しい鍵で更新できるという回答をもらえました。端末の回収を決める前に確認してよかったです。

この記事の時点では、入れ替えの方針と手順を確認したところです。新しい鍵を作る際は、キーストアだけでなくパスワードも保管したことを確認してから進めます。
