# 商談前カンペ生成

企業名・相手名を指定して、過去のやりとりから商談準備ガイド（カンペ）を生成し、LINEに配信する。

## 引数

`$ARGUMENTS` は以下の形式で受け取る:

- `[企業名 or 相手名]` — 過去データを検索するキーワード
- `[企業名] [送信先名]` — 送信先も指定
- 引数なしの場合 — ユーザーに企業名と送信先を確認する

## 実行手順

### Step 1: 過去データの検索

1. `search-messages` で企業名・相手名をキーワード検索（limit: 200）
2. `list-channels` でチャネル一覧を取得し、チャネル名に企業名を含むものを特定
3. 該当チャネルがあれば `list-messages` で直近の会話履歴も取得
4. 複数チャネルにまたがる場合はすべて収集する

### Step 2: 過去データの分析

収集したデータから以下を抽出する:

1. **相手の基本情報**: 担当者名、役職、連絡頻度、コミュニケーションスタイル
2. **過去の商談経緯**: これまでの提案内容、相手の反応、進捗状況
3. **相手の関心事**: よく話題にするテーマ、質問の傾向
4. **過去の懸念・反論**: 値段、スケジュール、競合比較など
5. **合意済み事項**: 既に決まっていること
6. **未解決事項**: 前回持ち越しになった課題

### Step 3: カンペの生成

以下の構成で商談準備ガイドを作成する:

#### A. オープニング（最初の5分）

- 挨拶の切り出し方（具体的なセリフ）
- 前回からの変化に触れるトーク例
- アイスブレイクのネタ（相手の関心事ベース）

#### B. 確認事項（前回の続き）

- 前回の宿題・持ち越し事項の確認セリフ
- 「前回〇〇とおっしゃっていましたが、その後いかがですか？」形式

#### C. 今回のゴール設定

- この商談で合意を取りたいポイント
- 最低限達成したいライン

#### D. 想定Q&A

- 相手が聞いてきそうな質問と回答案
- 過去の懸念点への対応セリフ

#### E. クロージング

- 次回アクションの提案セリフ
- 期限の切り方（「来週の〇曜日までに〜」形式）

### Step 4: 送信先の特定

1. `list-connect-users` でLINEユーザー一覧を取得（type: "LINE"）
2. 送信先をユーザーに確認する（**必ず確認してから送信すること**）

### Step 5: LINEへ配信

`send-line-message` でFlexメッセージとして送信する。

#### メッセージフォーマット

カンペは情報量が多いため、carousel形式で複数バブルに分割する:

**バブル1: 概要 + オープニング**

```json
{
  "type": "bubble",
  "size": "giga",
  "header": {
    "type": "box",
    "layout": "vertical",
    "contents": [
      { "type": "text", "text": "商談カンペ", "weight": "bold", "size": "lg" },
      {
        "type": "text",
        "text": "[企業名] | [日付]",
        "size": "xs",
        "color": "#999999"
      }
    ]
  },
  "body": {
    "type": "box",
    "layout": "vertical",
    "spacing": "md",
    "contents": [
      {
        "type": "text",
        "text": "オープニング",
        "weight": "bold",
        "size": "sm"
      },
      {
        "type": "text",
        "text": "挨拶・アイスブレイク案...",
        "size": "sm",
        "wrap": true
      }
    ]
  }
}
```

**バブル2: 確認事項 + ゴール**

**バブル3: 想定Q&A + クロージング**

## LLM出力ポリシー（厳守）

- **すべて具体的なセリフ・文面で出力**: 「ヒアリングする」→「『現在の〇〇についてお聞かせいただけますか？具体的には〜』と聞く」
- **相手の過去発言を引用**: 「前回『△△が課題だ』とおっしゃっていたので、今回は□□を提案する」
- **抽象的なアドバイス禁止**: 「信頼関係を構築する」のような抽象表現は使わない
- **LINE表示前提**: 箇条書き中心、セリフは「」で囲む、スクロール最小限

## 注意事項

- 過去データが少ない場合は、その旨をユーザーに伝え、手持ち情報の入力を促す
- 送信前に必ずユーザーに内容と送信先を確認すること
- carouselのバブルは最大12枚だが、3〜4枚に収めること
